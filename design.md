# Bamboo Content Hub — design guidelines

## Принцип

Интерфейс должен быть спокойным, очевидным и функциональным. Визуальное направление опирается на принципы интерфейсов Apple: сильная иерархия, системная типографика, большие зоны нажатия, много свободного пространства, минимум визуального шума и progressive disclosure. Это не буквальная копия iOS/macOS.

## Светлая оболочка

Пользовательская оболочка по умолчанию и независимо от системной темы работает в светлом режиме. Причина — контент, фотографии изделий и длинные формы должны оставаться визуально стабильными на телефоне, планшете и рабочем компьютере.

Базовые токены:

- фон приложения: `#f5f5f7`;
- основная поверхность: `#ffffff`;
- основной текст: `#1d1d1f`;
- вторичный текст: `#6e6e73`;
- граница: `#e5e5ea`;
- основной акцент: `#0071e3`;
- основной radius: `24px`;
- тени — только мягкие и малоконтрастные.

Тёмная тема может быть добавлена позднее только как явный переключатель с отдельной приёмкой; автоматическое переключение через `prefers-color-scheme` не должно менять внешний вид рабочего интерфейса.

## Иерархия

- На экране один главный CTA.
- Первичный контент важнее навигации и служебных статусов.
- Технические сущности (`delivery`, token scopes, webhook, raw IDs) не показываются без необходимости.
- Ошибка описывает, что произошло и что можно сделать дальше.
- Настройка сложного сервиса раскрывается по запросу; обзор страницы остаётся компактным.

## Сетка и размеры

- Desktop sidebar: `252px`.
- Содержимое: до `1240px`, центрируется внутри рабочей области.
- Страница подключений: не более двух колонок; при ширине до `1180px` — одна колонка.
- Mobile: основная навигация снизу.
- Touch target: не меньше `44×44 CSS px`.
- Контрольные viewport: `320px`, `390×844`, `768px`, `1024px`, `1280px`, `1440×900`.

## Типографика

Системный стек: `-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", sans-serif`. Заголовки используют отрицательный tracking только на крупных размерах. Текст интерфейса — по-русски, без инженерного жаргона.

## Подключения

Карточка площадки в закрытом состоянии показывает только:

- название и назначение;
- понятный статус;
- следующее рекомендуемое действие;
- одну основную кнопку.

OAuth-реквизиты, callback URL, ручные ID и дополнительные параметры находятся внутри раскрываемого блока. В каждый момент пользователь работает только с одной раскрытой карточкой. Автоматический выбор страницы/доски/стены имеет приоритет; ручной ID остаётся fallback.

## Движение и доступность

- Анимация используется только для ориентации.
- `prefers-reduced-motion` обязателен.
- Все интерактивные элементы имеют заметный `focus-visible`.
- Информация не кодируется одним цветом: статус всегда сопровождается текстом.
- Навигация отмечает текущий раздел через `aria-current`.

## Формы

Не показывать десятки полей одновременно. Основной flow: базовая карточка → медиа → ИИ → публикация. Второстепенные характеристики и ручные идентификаторы раскрываются по запросу.

## Опасные действия

Отключение интеграции, удаление и разрушительные действия требуют явного подтверждения. Токены и Client Secret никогда не отображаются полностью после сохранения.
