# ИИ-контент: готовый runtime-промпт

## Где находится рабочий промпт

Единственный пользовательский источник промпта — страница конкретного изделия: **Изделия → изделие → Импорт из ИИ** (`/products/{id}/ai`). Канонический генератор — `app/ai_pack.py::build_prompt()`.

Промпт не хранится как статический текст для ручного редактирования. При открытии страницы Bamboo Content Hub формирует его заново из текущего состояния приложения и конкретного изделия. В готовый запрос входят:

- `request_id` этого изделия;
- известные факты;
- технические идентификаторы медиа `image_1...N` в текущем порядке;
- полный контракт ответа;
- правила Bamboo Pottery;
- отдельные требования Instagram, VK, Telegram, Pinterest, Facebook, TikTok, YouTube и Ярмарки мастеров;
- актуальная JSON Schema `bamboo-content-pack/1.0` из установленной версии Hub.

Статического промпта для копирования в этой документации нет специально: он может устареть и не содержит данных конкретного изделия.

## Пошаговый порядок

1. Создайте изделие и внесите все известные подтверждённые характеристики.
2. Загрузите фото/видео в нужном порядке.
3. Откройте **Импорт из ИИ**. Рядом с медиа Hub показывает соответствие `image_1`, `image_2` и далее.
4. Нажмите **Скопировать готовый запрос**. Ничего в нём не дописывайте и не заменяйте вручную.
5. Вставьте запрос в мультимодальную модель и приложите те же медиа в том же порядке.
6. Модель должна вернуть ровно один JSON-объект без Markdown, комментариев и текста вокруг него.
7. Вставьте ответ в Hub и нажмите **Проверить**.
8. Просмотрите `needs_confirmation` и `assumptions`, затем нажмите **Импортировать**.
9. Перед публикацией выберите площадки, медиа, время и параметры, которые требуют решения человека.

Если после открытия страницы карточка или медиа изменились, нажмите **Обновить из карточки**. Страница перезагрузится и заново сформирует полный рабочий запрос.

## Что ИИ обязан подготовить

Общий блок `content` содержит `headline`, `short_description`, `full_description`, `story`, `call_to_action`. Дополнительно создаётся отдельный вариант для каждой площадки — не копии одного текста.

| Площадка | Что формируется | Редакционный смысл |
|---|---|---|
| Instagram | `caption`, `hashtags` | Самостоятельный живой пост и точные хэштеги. |
| VK | `text`, `hashtags` | Более информативный самостоятельный текст. |
| Telegram | `text`, `button_text`, `button_url` | Короткое сообщение; кнопка только при реальной ссылке. |
| Pinterest | `title`, `description`, `keywords`, `board_suggestion`, `destination_url` | Поисково-понятное описание; URL только из исходных данных. |
| Facebook | `text` | Самостоятельный естественный пост, не копия Instagram/VK. |
| TikTok | `caption`, `hashtags`, `privacy` | Короткая подпись; `privacy` всегда `null`, решение принимает человек. |
| YouTube | `title`, `description`, `tags` | Конкретный заголовок и фактическое описание. |
| Ярмарка мастеров | `title`, `short_description`, `description`, `keywords`, `category_suggestion` | Полноценная карточка товара; категория только как рекомендация. |

В `hashtags` значения записываются с `#`. В `keywords` и `tags` — без `#`. Один и тот же набор хэштегов не должен одновременно дублироваться внутри `caption`/`text`.

## Контракт ответа

Runtime-промпт требует от модели:

- вернуть ровно один JSON-объект;
- сохранить `schema_version=bamboo-content-pack/1.0` и точный `request_id`;
- вернуть все корневые разделы: `product`, `visual`, `content`, `channels`, `media`, `needs_confirmation`, `assumptions`;
- не добавлять полей вне JSON Schema;
- заполнить отдельный объект каждой запрошенной площадки;
- для `media.images` вернуть существующие `image_1...N`, `media.order` и `recommended_cover`;
- перед выдачей проверить валидность JSON, идентификаторы медиа, отсутствие выдуманных фактов и URL.

В протоколе `bamboo-content-pack/1.0` технический идентификатор имеет вид `image_N` даже если конкретное вложение является видео. В интерфейсе рядом с каждым файлом показан его фактический идентификатор.

## Редакционные и фактологические правила

- Известные данные пользователя — источник истины.
- По фото/видео допускается описывать только наблюдаемые признаки.
- Нельзя выдумывать цену, материал, размеры, объём, массу, состав глазури, режим обжига, пищевую безопасность, ПММ/СВЧ, наличие, сроки, скидки, ссылки и доставку.
- Неизвестный факт остаётся `null`/пустым согласно JSON Schema и при необходимости превращается в вопрос в `needs_confirmation`.
- Любое предположение записывается в `assumptions` и не используется в тексте площадки как установленный факт.
- URL нельзя генерировать из головы. `button_url` и `destination_url` остаются пустыми, если ссылка не дана.
- Настройки публикации, согласия и приватность не выбираются моделью. Например, `channels.tiktok.privacy` остаётся `null`.
- Тон Bamboo Pottery: спокойный, тёплый, человеческий, конкретный; без канцелярита, давления и рекламных клише.

## Проверка и импорт

Цепочка импорта: extraction → `json.loads` → Pydantic → domain rules → проверка `request_id` → merge. `eval` не используется. Существующие человеческие значения имеют приоритет; ИИ заполняет пустые поля.

Если импорт отклонён, сначала проверьте: ответ является одним JSON-объектом; `schema_version` равен `bamboo-content-pack/1.0`; `request_id` не изменён; нет лишних полей; ссылки на медиа существуют; числовые значения попадают в допустимые диапазоны схемы.
