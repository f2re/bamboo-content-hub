# ИИ-контент: порядок работы и промпт

## Где находится рабочий промпт

Единственный канонический генератор промпта — `app/ai_pack.py::build_prompt()`. Для каждого изделия Bamboo Content Hub создаёт собственный `request_id`, добавляет известные факты, перечисляет медиа в порядке загрузки и прикладывает актуальную JSON Schema `bamboo-content-pack/1.0`.

В интерфейсе готовый запрос находится здесь: **Изделия → изделие → Импорт из ИИ** (`/products/{id}/ai`). Именно его нужно копировать в модель. Не используйте статический пример вместо рабочего запроса: другой `request_id` будет отклонён при импорте.

## Пошаговый порядок

1. Создайте изделие и заполните известные характеристики: название, артикул, тип, цену, материалы, размеры и другие подтверждённые сведения.
2. Загрузите фото/видео. Порядок важен: хаб передаёт модели идентификаторы `image_1`, `image_2` и далее по порядку прикрепления.
3. Откройте **Подготовка с ИИ** и скопируйте сформированный запрос.
4. Вставьте запрос в мультимодальную модель и приложите те же медиа в том же порядке. Если модель не умеет анализировать конкретный тип медиа, она не должна додумывать его содержимое.
5. Модель должна вернуть один JSON без Markdown, комментариев и текста вокруг него.
6. Вставьте ответ в хаб и нажмите **Проверить**.
7. Хаб сам выделит цену, материалы, размеры, обжиг, уход и наличие как критичные факты. Такие значения не импортируются автоматически даже если модель ошибочно подала их как достоверные.
8. Отметьте галочкой только те критичные значения, которые вы действительно можете подтвердить. Подтверждение подписывается сервером и относится к конкретному `request_id`, пути и значению.
9. Отдельно просмотрите обычные вопросы `needs_confirmation` и явно помеченные `assumptions`.
10. Нажмите **Применить подтверждённое**. Существующие значения пользователя не перезаписываются; неподтверждённые критичные факты остаются пустыми.
11. В карточке изделия при необходимости поправьте тексты. Затем выберите площадки, медиа, время публикации и параметры, которые требуют решения человека.

Прямой вызов import API без предварительного preview безопасен: новые критичные значения из сырого ответа модели будут исключены. Модель не может самостоятельно выставить `confirmed=true`, потому что для восстановления значения требуется HMAC-подпись, которую создаёт только Bamboo Content Hub.

## Что ИИ обязан подготовить

Общий блок `content` содержит универсальную основу: `headline`, `short_description`, `full_description`, `story`, `call_to_action`. Дополнительно создаётся отдельный вариант под каждую площадку — это не копии одного текста.

| Площадка | Что формируется | Редакционный смысл |
|---|---|---|
| Instagram | `caption`, `hashtags` | Живой текст о предмете/процессе, короткие абзацы, несколько точных хэштегов. |
| VK | `text`, `hashtags` | Более информативная версия с характеристиками и уместным призывом. |
| Telegram | `text`, `button_text`, `button_url` | Короткое сообщение подписчикам мастерской; кнопка только при реальной ссылке. |
| Pinterest | `title`, `description`, `keywords`, `board_suggestion`, `destination_url` | Поисково-понятное описание; доска — рекомендация; URL только из исходных данных. |
| Facebook | `text` | Самостоятельный естественный пост, который не дублирует Instagram слово в слово. |
| TikTok | `caption`, `hashtags`, `privacy` | Короткая подпись; `privacy` всегда `null`, потому что видимость и декларации выбирает человек. |
| YouTube | `title`, `description`, `tags` | Конкретный заголовок и фактическое описание видео/изделия без выдуманных сцен. |
| Ярмарка мастеров | `title`, `short_description`, `description`, `keywords`, `category_suggestion` | Полноценная карточка товара на подтверждённых фактах; категория — только рекомендация. |

В `hashtags` значения записываются уже с `#`. В `keywords` и `tags` — без `#`.

## Редакционные и фактологические правила

- Известные данные пользователя — источник истины.
- По фото/видео допускается описывать только наблюдаемые признаки: цвет, форма, фактура, видимые детали, композиция кадра.
- Нельзя выдумывать цену, материал, размеры, объём, массу, состав глазури, режим обжига, пищевую безопасность, ПММ/СВЧ, наличие, сроки, скидки, ссылки и доставку.
- Даже если модель нарушила это правило и заполнила критичное значение, хаб переносит его в отдельное серверно подписанное подтверждение и не пишет в карточку без галочки пользователя.
- Неизвестный факт остаётся `null`/пустым и при необходимости превращается в вопрос в `needs_confirmation`.
- Любое предположение записывается в `assumptions` и не используется в публикационном тексте как установленный факт.
- Тон Bamboo Pottery: спокойный, тёплый, человеческий, конкретный; без канцелярита, давления и рекламных клише.
- URL нельзя генерировать из головы. `button_url` и `destination_url` остаются пустыми, если ссылка не дана во входных данных.
- Настройки публикации, согласия и приватность не выбираются моделью. Например, `channels.tiktok.privacy` остаётся `null`.
- Для `media` используются только реально загруженные `image_1...N`; ссылки на отсутствующие медиа блокируют импорт.
- Служебные поля `needs_confirmation[].value/proof/confirmed` заполняет хаб. Внешняя модель не должна их создавать.

## Provenance

Для характеристик изделия хаб хранит источник в `facts._provenance`:

- `user` — значение уже было в карточке пользователя;
- `ai` — некритичное значение добавлено из структурированного ответа ИИ;
- `confirmed` — критичное значение добавлено только после явного подтверждения пользователя.

Служебный `_provenance` не попадает обратно в промпт модели.

## Базовый промпт

Ниже — читаемая основа. Рабочий запрос из интерфейса содержит ещё `request_id`, список медиа, правила конкретных каналов, факты изделия и полную JSON Schema.

```text
Ты — контент-редактор гончарной мастерской Bamboo Pottery.

Верни ТОЛЬКО один валидный JSON без Markdown и пояснений.
Используй schema_version bamboo-content-pack/1.0 и request_id <request_id>.
Медиа идут в порядке прикрепления и внутри схемы называются: image_1...N.
Подготовь отдельный вариант контента для запрошенных площадок.

Считай известные данные пользователя источником истины. По вложенным медиа
описывай только то, что действительно видно или слышно. Никогда не придумывай
характеристики, цену, наличие, сроки, ссылки или условия доставки. Неизвестное
оставляй пустым и добавляй короткий вопрос в needs_confirmation. Предположения
помечай в assumptions и не подавай их как факты.

Сформируй общий content и отдельный, реально адаптированный текст для каждой
площадки. Не копируй один текст во все каналы. Пиши естественно, короткими
абзацами, без рекламных клише. URL не выдумывай. Параметры публикации и
согласия, которые должен выбрать человек, не угадывай; TikTok privacy = null.

Требования по площадкам:
<правила только для запрошенных каналов>

Известные данные пользователя:
<JSON с фактами изделия>

JSON Schema:
<актуальная схема bamboo-content-pack/1.0>
```

## Проверка и импорт

Цепочка импорта: extraction → `json.loads` → Pydantic → `request_id` → серверная защита критичных фактов → проверка реальных media refs → merge. `eval` не используется. Существующие человеческие значения имеют приоритет; ИИ заполняет пустые поля.

JSON Schema из `spec/bamboo-content-pack-1.0.schema.json` проверяется тестом на точное соответствие `BambooContentPack.model_json_schema()`, поэтому изменение Pydantic-модели без обновления схемы ломает CI.

Если импорт отклонён, сначала проверьте: ответ является одним JSON-объектом; `schema_version` равен `bamboo-content-pack/1.0`; `request_id` не изменён; нет лишних полей; ссылки на медиа существуют; числовые значения попадают в допустимые диапазоны схемы.
