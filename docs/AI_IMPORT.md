# ИИ-контент: готовый запрос из интерфейса

## Где находится рабочий промпт

Единственный пользовательский источник рабочего промпта — **Изделия → нужное изделие → Подготовка с ИИ** (`/products/{id}/ai`). Канонический генератор — `app/ai_pack.py::build_prompt()`.

Промпт не хранится как статический шаблон для ручного редактирования. При открытии страницы Bamboo Content Hub формирует его из текущего состояния конкретного изделия. В запрос автоматически входят:

- точный `request_id`;
- известные факты изделия без служебного provenance;
- текущий порядок фото/видео и идентификаторы `image_1...N`;
- правила редакционного стиля Bamboo Pottery;
- требования Instagram, VK, Telegram, Pinterest, Facebook, TikTok, YouTube и Ярмарки мастеров;
- правила безопасной работы с неизвестными и критичными фактами;
- актуальная JSON Schema `bamboo-content-pack/1.0` из установленной версии приложения.

Статического промпта для копирования в README или документации нет специально: такой текст может устареть и не содержит данных конкретного изделия.

## Порядок работы

1. Создайте изделие и внесите известные подтверждённые характеристики.
2. Загрузите фото/видео и расположите их в нужном порядке.
3. Откройте **Подготовка с ИИ**. Hub показывает рядом с каждым файлом его имя `image_1`, `image_2` и далее.
4. Нажмите **Скопировать готовый запрос**. Ничего не добавляйте и не заменяйте в нём вручную.
5. Вставьте запрос в мультимодальную модель и приложите те же файлы в том же порядке.
6. Скопируйте один JSON-объект из ответа модели обратно в Hub.
7. Нажмите **Проверить**.
8. Подтвердите только те критичные факты, которые знаете наверняка.
9. Просмотрите `needs_confirmation` и `assumptions`.
10. Нажмите **Применить подтверждённое**.

Если карточка или порядок медиа изменились после открытия страницы, нажмите **Обновить из карточки**. Страница перезагрузится и сформирует полный запрос заново.

## Что формирует ИИ

Общий блок `content` содержит `headline`, `short_description`, `full_description`, `story`, `call_to_action`. Для каждой площадки формируется самостоятельный вариант, а не копия одного текста.

| Площадка | Поля |
|---|---|
| Instagram | `caption`, `hashtags` |
| VK | `text`, `hashtags` |
| Telegram | `text`, `button_text`, `button_url` |
| Pinterest | `title`, `description`, `keywords`, `board_suggestion`, `destination_url` |
| Facebook | `text` |
| TikTok | `caption`, `hashtags`, `privacy` (`null`, выбирает человек) |
| YouTube | `title`, `description`, `tags` |
| Ярмарка мастеров | `title`, `short_description`, `description`, `keywords`, `category_suggestion` |

В `hashtags` значения записываются с `#`; в `keywords` и `tags` — без `#`.

## Что ИИ не имеет права выдумывать

Цена, материал, размеры, объём, масса, состав глазури, режим обжига, пищевой контакт, ПММ/СВЧ, наличие, сроки, скидки, URL, условия доставки и другие не подтверждённые характеристики не должны превращаться в факты.

По фото/видео допустимы наблюдаемые признаки: цвет, форма, фактура, видимые детали и композиция. Предположение должно находиться в `assumptions`, а отсутствующий важный факт — оставаться пустым и при необходимости становиться вопросом в `needs_confirmation`.

Служебные поля `needs_confirmation[].value`, `proof` и `confirmed` модель не заполняет. Их использует сам Hub после проверки ответа.

## Критичные факты и подтверждение

Цена, материалы, глазурь, режим обжига, размеры, масса, правила ухода/использования и наличие считаются критичными. Даже если модель заполнила такое поле, Bamboo Content Hub не переносит новый критичный факт в карточку молча.

После **Проверить** Hub:

1. отделяет новый критичный факт;
2. связывает подтверждение с конкретными `request_id`, путём поля и значением;
3. создаёт серверную HMAC-подпись;
4. показывает значение пользователю;
5. импортирует его только после явного подтверждения.

Прямой вызов import API без preview также безопасен: неподтверждённые новые критичные значения исключаются. Подделка `confirmed=true` без корректной серверной подписи не даёт модели возможности записать факт.

## Provenance

Для характеристик изделия хранится источник в `facts._provenance`:

- `user` — значение было внесено пользователем;
- `ai` — некритичный факт был заполнен из структурированного ответа ИИ;
- `confirmed` — критичный факт был принят после явного подтверждения.

`_provenance` — внутренние данные; они не отправляются обратно модели в следующем промпте.

## Медиа

Импорт может ссылаться только на реально существующие `image_1...N`, соответствующие текущему порядку медиатеки изделия. Hub проверяет ссылки относительно фактических файлов; ссылка на отсутствующий идентификатор блокирует импорт.

В протоколе `bamboo-content-pack/1.0` техническое имя имеет форму `image_N` даже если вложение является видео. На странице **Подготовка с ИИ** рядом с каждым превью показаны и техническое имя, и исходное имя файла.

## Проверка и импорт

Цепочка: extraction → `json.loads` → Pydantic → `request_id` → защита критичных фактов → проверка media refs → merge. `eval` не используется. Уже заполненные человеком значения имеют приоритет.

JSON Schema в `spec/bamboo-content-pack-1.0.schema.json` проверяется CI на точное соответствие `BambooContentPack.model_json_schema()`.

Если ответ отклонён, проверьте: это один JSON-объект; `schema_version` равен `bamboo-content-pack/1.0`; `request_id` не изменён; нет полей вне схемы; `image_N` действительно существует; числовые значения попадают в диапазоны схемы.
