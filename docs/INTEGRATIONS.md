# Подключения и публикация

Bamboo Content Hub 0.3.0 поддерживает три режима, которые не следует смешивать:

1. **Без приложения** — основной путь для VK, Instagram, Facebook, Pinterest, TikTok и YouTube. Hub готовит пакет, пользователь публикует через обычный интерфейс площадки.
2. **Через браузер** — основной путь для Ярмарки мастеров. Пользователь авторизуется штатно, а локальный помощник заполняет видимые поля формы.
3. **Автоматически через официальный API** — дополнительный режим для полностью автоматической отправки.

n8n не требуется. Браузерные cookies, пароли и закрытые внутренние endpoints сайтов не копируются и не хранятся.

## Режим без приложения

По умолчанию он используется для:

- VK;
- Instagram;
- Facebook;
- Pinterest;
- TikTok;
- YouTube.

### Порядок работы

1. Откройте изделие.
2. Выберите площадки и медиа.
3. Нажмите **Опубликовать**.
4. В разделе **Публикации** откройте пакет нужной площадки.
5. Скопируйте готовый текст.
6. Скачайте материалы ZIP-архивом либо отдельными файлами.
7. Нажмите **Открыть площадку**, вставьте текст и загрузите медиа.
8. После фактической публикации отметьте пакет как опубликованный. Ссылку можно сохранить, но это необязательно.

### Что входит в пакет

- отдельный текст конкретной площадки;
- заголовок, если он нужен каналу;
- выбранные фото и видео в сохранённом порядке;
- `publication.txt`;
- ZIP со всеми файлами;
- прямой переход на площадку;
- отметка результата в истории Bamboo.

### Что выбирается на площадке

Динамические настройки не угадываются Hub и задаются пользователем штатно:

- видимость;
- музыка;
- коммерческие и рекламные декларации;
- доска Pinterest;
- профиль, страница или сообщество;
- обложка/превью;
- иные параметры, зависящие от текущего аккаунта.

## Ярмарка мастеров: browser-assisted режим

Ярмарка мастеров обслуживается не через закрытые запросы сайта, а через обычную авторизацию пользователя в браузере.

### Один раз

1. Подготовьте любую публикацию для Ярмарки мастеров и откройте её пакет.
2. Перетащите кнопку **Bamboo → заполнить Ярмарку** на панель закладок.
3. Если перетаскивание недоступно, нажмите кнопку: Bamboo скопирует JavaScript URL, который можно вставить в поле адреса новой закладки.

### Для каждой работы

1. В Bamboo нажмите **Скопировать данные для помощника**.
2. Откройте `livemaster.ru` и войдите обычным способом.
3. Откройте штатную форму добавления работы.
4. Нажмите закладку **Bamboo → заполнить Ярмарку**.
5. Помощник ищет поля по `label`, `name`, `id`, `placeholder` и ARIA-подписям.
6. Заполняются только пустые поля:
   - название;
   - краткое описание;
   - полное описание;
   - цена;
   - материалы;
   - размеры;
   - ключевые слова;
   - наличие.
7. Помощник показывает отчёт: что заполнено, что не найдено и что не было перезаписано.
8. Загрузите фотографии из ZIP и завершите публикацию вручную.

В ZIP дополнительно находится `browser-fill.json`. Его schema:

```json
{
  "schema": "bamboo-browser-fill/1",
  "platform": "livemaster",
  "title": "...",
  "short_description": "...",
  "description": "...",
  "price": 4200,
  "currency": "RUB",
  "materials": "каменная масса, глазурь",
  "dimensions": "высота 90 мм, диаметр 140 мм",
  "keywords": "керамика, чаша, ручная работа",
  "availability": "В наличии"
}
```

### Граница безопасности

Помощник:

- читает только JSON из буфера обмена;
- работает локально внутри открытой страницы;
- не читает `document.cookie`, пароль, local storage или сетевые запросы;
- не вызывает `fetch`, `XMLHttpRequest` или API Bamboo;
- не перезаписывает непустые поля;
- не нажимает кнопку публикации;
- не загружает файлы скрытно: браузер запрещает программно выбирать локальные файлы без действия пользователя.

Если сайт изменил названия полей, пакет показывает каждое значение отдельно с кнопкой копирования.

## Почему не cookies

Авторизационная cookie обычно даёт доступ ко всей браузерной сессии, зависит от CSRF-токенов, устройства, IP и внутренних запросов сайта. Такой поток нестабилен и небезопасен как основа продукта.

Bamboo сохраняет более узкую модель:

- сессия соцсети остаётся в браузере пользователя;
- пароль не передаётся Hub;
- cookies не записываются в БД;
- скрытые web-endpoints не повторяются;
- пользователь видит итоговую публикацию перед отправкой.

## Матрица режимов

| Канал | Основной режим | Дополнительный режим | Медиа пакета |
|---|---|---|---|
| Telegram | Bot API | — | текст, фото, видео |
| VK | без приложения | официальный API | текст, фото, видео |
| Instagram | без приложения | Meta Graph API | фото, карусель, видео |
| Facebook | без приложения | Meta Graph API | текст, фото, видео |
| Pinterest | без приложения | Pinterest API | одно изображение |
| TikTok | без приложения | Content Posting API | одно видео или до 35 фото |
| YouTube | без приложения | YouTube Data API | одно видео и метаданные |
| Ярмарка мастеров | через браузер | — | поля карточки и медиа |

## Реальные требования официальных API

Расширенный режим может не заработать только от Client ID/Secret: площадки устанавливают дополнительные требования.

### YouTube

Для автоматической загрузки нужны:

- Google Cloud project;
- включённый YouTube Data API;
- OAuth client;
- аккаунт с YouTube channel;
- OAuth consent и нужные scopes;
- иногда верификация приложения в зависимости от режима публикации и аудитории.

### Pinterest

Для API-публикации обычно нужны:

- Pinterest business account;
- developer app;
- App ID/Secret и redirect URI;
- OAuth scopes;
- доступ trial или standard, одобренный Pinterest;
- выбранный `board_id`.

### TikTok

Direct Post может требовать:

- TikTok developer app;
- Login Kit и Content Posting API;
- тестовых пользователей;
- review/audit приложения;
- подтверждённый публичный HTTPS-домен для photo pull;
- соблюдение ограничений самого подключённого аккаунта.

До аудита публикация через API может быть ограничена приватной видимостью.

### Meta / Instagram / Facebook

Instagram API publishing требует:

- Instagram Professional account;
- связанную Facebook Page;
- Meta app;
- необходимые permissions и access review;
- публичный HTTPS URL для медиа.

Facebook автоматическая публикация выполняется на Page, а не в произвольный личный профиль, и также требует Meta app и permissions.

### VK

Для полного автоматического сценария нужны:

- приложение;
- пользовательская авторизация и access token с нужными правами;
- доступ к выбранной стене/сообществу;
- разрешённые методы загрузки и публикации.

Ключ сообщества не считается универсальной заменой всему пользовательскому flow с загрузкой медиа и `wall.post`.

## Telegram

Telegram остаётся простым автоматическим каналом:

1. Откройте BotFather.
2. Создайте бота командой `/newbot`.
3. Добавьте его администратором канала с правом публикации.
4. В Bamboo укажите токен и `@имя_канала`.
5. Сохраните и проверьте подключение.

## Автоматический API-режим

На странице **Подключения** раскройте сервис и откройте **Автоматически через официальный API — расширенный режим**.

Общий порядок:

1. Проверить требования площадки к типу аккаунта.
2. Создать developer app.
3. Скопировать callback из Bamboo.
4. Сохранить Client ID/Secret.
5. Выполнить OAuth.
6. При необходимости пройти review/audit.
7. Выбрать доску, страницу или стену.
8. Проверить подключение и сделать тестовую приватную публикацию.

Реквизиты и токены хранятся зашифрованно. Значения из `.env` продолжают работать как fallback.

## Callback URL и HTTPS

Callback строится так:

```text
<APP_BASE_URL>/oauth/<provider>/callback
```

Для реального OAuth большинство провайдеров требуют публичный HTTPS-адрес. Локальный `http://192.168.x.x` подходит для самого Hub в LAN, но обычно не подходит как внешний callback.

## Совместимость существующих подключений

Если уже есть access token, OAuth Client ID или переменные провайдера в `.env`, Bamboo сохраняет автоматический режим. Можно переключиться на режим без приложения; реквизиты при этом не удаляются.

## Диагностика версии

В UI должна отображаться версия `v0.3.0 · без приложений`.

```bash
curl -fsS http://localhost:8080/health/version
```

Ответ должен содержать:

```text
manual-first-browser-assist
```

Если в интерфейсе всё ещё показано «Начните с создания OAuth-приложения», сервер или браузер использует старую версию. Запустите `./scripts/update.sh`, затем выполните жёсткое обновление страницы.

## Проверка

CI проверяет:

- создание изделия при строгой CSP;
- manual/automatic mode selection;
- отсутствие внешнего API в ручном режиме;
- создание пакета и ZIP;
- browser-assisted пакет Ярмарки мастеров;
- отсутствие доступа helper к cookies и сети;
- завершение ручной публикации;
- обратную совместимость OAuth;
- adapter payload, retry/status flow;
- Docker build и JavaScript syntax.

Реальные внешние публикации не выполняются в CI, поскольку требуют пользовательских аккаунтов, токенов, подтверждённых доменов и review провайдеров.
