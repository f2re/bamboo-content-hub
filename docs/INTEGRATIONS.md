# Подключения и публикация

Bamboo Content Hub поддерживает два независимых режима:

1. **Без приложения** — основной и самый простой путь. Hub готовит пакет, а пользователь публикует его через обычный интерфейс площадки.
2. **Автоматически через официальный API** — дополнительный режим для полностью автоматической отправки.

n8n не требуется. Браузерные cookies, пароли и закрытые внутренние endpoints сайтов не копируются и не хранятся.

## Режим без приложения

По умолчанию он используется для:

- VK;
- Instagram;
- Facebook;
- Pinterest;
- TikTok;
- YouTube.

### Порядок работы

1. Откройте изделие.
2. Выберите площадки и медиа.
3. Нажмите **«Опубликовать»**.
4. В разделе **«Публикации»** откройте пакет нужной площадки.
5. Скопируйте готовый текст.
6. Скачайте все материалы ZIP-архивом либо отдельными файлами.
7. Нажмите **«Открыть площадку»**, вставьте текст и загрузите медиа.
8. После фактической публикации отметьте пакет как опубликованный. Ссылку на пост можно сохранить, но это необязательно.

### Что входит в пакет

- отдельный текст конкретной площадки;
- заголовок, если он нужен каналу;
- выбранные фото и видео в сохранённом порядке;
- `publication.txt`;
- ZIP со всеми файлами;
- прямой переход на площадку;
- отметка результата в истории Bamboo.

### Что выбирается на площадке

Динамические настройки не угадываются Hub и задаются пользователем штатно:

- видимость;
- музыка;
- коммерческие и рекламные декларации;
- доска Pinterest;
- профиль, страница или сообщество;
- обложка/превью, когда платформа рассчитывает её сама;
- иные параметры, зависящие от текущего аккаунта.

## Почему не cookies

Авторизационная cookie обычно даёт доступ ко всей браузерной сессии, зависит от CSRF-токенов, устройства, IP и внутренних запросов сайта. Такой поток нестабилен и небезопасен как основа продукта.

Bamboo сохраняет более узкую модель:

- сессия соцсети остаётся в браузере пользователя;
- пароль не передаётся Hub;
- cookies не записываются в БД;
- скрытые web-endpoints не повторяются;
- пользователь видит итоговую публикацию перед отправкой.

## Матрица режимов

| Канал | Без приложения | Официальный API | Медиа ручного пакета |
|---|---:|---:|---|
| Telegram | — | да, Bot API | текст, фото, видео |
| VK | да, по умолчанию | опционально | текст, фото, видео |
| Instagram | да, по умолчанию | опционально, Meta Graph API | фото, карусель, видео |
| Facebook | да, по умолчанию | опционально, Meta Graph API | текст, фото, видео |
| Pinterest | да, по умолчанию | опционально | одно изображение |
| TikTok | да, по умолчанию | опционально, Content Posting API | одно видео или до 35 фото |
| YouTube | да, по умолчанию | опционально, YouTube Data API | одно видео и метаданные |
| Ярмарка мастеров | да | нет | текст и медиа |

## Telegram

Telegram остаётся простым автоматическим каналом:

1. Откройте BotFather.
2. Создайте бота командой `/newbot`.
3. Добавьте его администратором канала с правом публикации.
4. В Bamboo укажите токен и `@имя_канала`.
5. Сохраните и проверьте подключение.

## VK

Основной режим — пакет без приложения. Bamboo готовит текст и медиа, пользователь открывает VK и публикует штатно.

Это сознательное решение: система не хранит cookies и не выдаёт ограниченный ключ сообщества за универсальную замену пользовательской авторизации для полного цикла публикации и загрузки медиа.

Автоматический OAuth/API-поток остаётся расширенным режимом для установок, где он уже настроен или действительно необходим.

## Instagram и Facebook

В ручном режиме Hub формирует отдельные пакеты для Instagram и Facebook. Пользователь выбирает аккаунт/страницу в самой платформе.

API-режим использует Meta OAuth, Facebook Page и связанный Instagram Professional account. Для автоматической загрузки Instagram медиа должны быть доступны по публичному HTTPS URL.

## Pinterest

Ручной пакет содержит одно изображение, заголовок, описание, ключевые слова и destination URL, если он был задан. Доска выбирается в Pinterest при создании Pin.

API-режим требует Pinterest developer app, OAuth scopes и выбранный `board_id`.

## TikTok

Ручной режим подготавливает одно видео либо набор фотографий и подпись. Видимость, музыка, AIGC и коммерческие декларации выбираются в TikTok перед публикацией.

API Direct Post остаётся расширенным режимом и может требовать review/audit, тестовых пользователей и подтверждённый публичный HTTPS-домен для фотографий.

## YouTube

Ручной пакет содержит одно видео, заголовок, описание и теги. Он открывает YouTube Studio; видимость выбирается там.

API-режим использует OAuth, resumable upload и последующую проверку обработки видео.

## Автоматический API-режим

На странице **«Подключения»** раскройте нужный сервис и откройте раздел **«Автоматически через официальный API — расширенный режим»**.

Общий порядок:

1. Создать developer app у провайдера.
2. Скопировать callback из Bamboo.
3. Сохранить Client ID/Secret.
4. Выполнить OAuth.
5. При необходимости выбрать доску, страницу или стену.
6. Проверить подключение и сделать тестовую приватную публикацию.

Реквизиты приложения и токены хранятся зашифрованно. Значения из `.env` продолжают работать как совместимый fallback.

## Callback URL и HTTPS

Callback строится так:

```text
<APP_BASE_URL>/oauth/<provider>/callback
```

Для реального OAuth большинство провайдеров требуют публичный HTTPS-адрес. Локальный `http://192.168.x.x` подходит для самого Hub в LAN, но обычно не подходит как внешний OAuth callback.

## Совместимость существующих подключений

Если в установленной системе уже есть access token, OAuth Client ID или переменные провайдера в `.env`, Bamboo сохраняет автоматический режим. Пользователь может вручную переключиться на режим без приложения; реквизиты при этом не удаляются и доступны для обратного переключения.

## Проверка

CI проверяет:

- manual/automatic mode selection;
- отсутствие вызова внешнего API в ручном режиме;
- создание пакета и ZIP;
- завершение ручной публикации;
- обратную совместимость OAuth;
- adapter payload, retry/status flow;
- сборку Docker и JavaScript syntax.

Реальные внешние публикации не выполняются в CI, поскольку требуют пользовательских аккаунтов, токенов, подтверждённых доменов и review провайдеров.
