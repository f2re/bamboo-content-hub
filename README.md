# Bamboo Content Hub

Локальный контент-центр Bamboo Pottery. Изделие и медиа создаются один раз, ИИ возвращает структурированный `Bamboo Content Pack`, а Hub готовит отдельные тексты и задания для публикации на разных площадках.

Текущая версия: **0.3.0**. В интерфейсе слева внизу должна отображаться строка `v0.3.0 · без приложений`. Машиночитаемая проверка: `GET /health/version`.

## Что работает

- каталог изделий и отдельная карточка каждого изделия;
- создание изделия при строгой Content Security Policy, включая fallback без JavaScript;
- загрузка и оптимизация фото/видео, порядок медиа, обложка и удаление;
- ручной редактор характеристик и текстов всех площадок;
- `bamboo-content-pack/1.0`: полный runtime prompt → preview/import → безопасное merge;
- черновики, расписание, независимые доставки, retries и idempotency;
- режим **«Без приложения»** для VK, Instagram, Facebook, Pinterest, TikTok и YouTube;
- browser-assisted карточки Ярмарки мастеров через обычную авторизацию пользователя;
- автоматический Telegram через BotFather;
- опциональные официальные API-адаптеры VK, Pinterest, Instagram, Facebook, TikTok и YouTube;
- OAuth state/PKCE/exchange/refresh/revoke и зашифрованное хранение реквизитов;
- светлый адаптивный PWA-интерфейс;
- SQLite WAL, Alembic, Docker Compose, backup/restore/update.

## Быстрый старт

```bash
git clone https://github.com/f2re/bamboo-content-hub.git
cd bamboo-content-hub
./scripts/install.sh
```

Откройте `http://localhost:8080`.

Проверка установленной версии:

```bash
curl -fsS http://localhost:8080/health/version
```

Ожидаемый маркер:

```json
{"version":"0.3.0","feature_marker":"manual-first-browser-assist"}
```

## Добавление изделия

Основная кнопка **«Добавить»** открывает диалог. Она больше не использует inline JavaScript, который блокировался строгой CSP.

Есть независимый fallback:

```text
/new-product
```

Поэтому создание работает также при отключённом JavaScript или если браузер не поддерживает `<dialog>`:

1. Откройте **Изделия**.
2. Нажмите **Добавить**.
3. Введите название.
4. Нажмите **Создать изделие**.
5. На следующем экране загрузите медиа и заполните карточку.

## ИИ: готовый запрос без ручной сборки

Рабочий промпт не надо брать из README и собирать по частям. Он формируется на лету для конкретного изделия на странице **Изделия → нужное изделие → Подготовка с ИИ** (`/products/{id}/ai`).

Bamboo автоматически подставляет:

- текущий `request_id`;
- известные факты изделия;
- количество и порядок фото/видео (`image_1...N`);
- редакционные правила Bamboo Pottery;
- отдельные требования площадок;
- контракт ответа и актуальную JSON Schema.

Порядок работы:

1. Нажмите **Скопировать готовый запрос**.
2. Вставьте его в мультимодальную модель и приложите показанные медиа в том же порядке.
3. Скопируйте один JSON-ответ обратно в Hub.
4. Нажмите **Проверить**, затем **Импортировать**.

ИИ не должен придумывать цену, материалы, размеры, объём, массу, глазурь, режим обжига, пищевую безопасность, ПММ/СВЧ, наличие, сроки, скидки, ссылки или доставку. Критичные факты не записываются без явного подтверждения человека.

Полная инструкция: [docs/AI_IMPORT.md](docs/AI_IMPORT.md).

## Основной путь: публикация без developer app

Для VK, Instagram, Facebook, Pinterest, TikTok и YouTube режим **«Без приложения»** включён по умолчанию. Для него не нужны n8n, Client ID, callback URL, OAuth, business API или браузерные cookies.

Порядок:

1. В карточке изделия выберите площадки и медиа.
2. Нажмите **Опубликовать**.
3. В разделе **Публикации** нажмите **Открыть пакет** у нужной площадки.
4. Скопируйте готовый текст.
5. Скачайте медиа одним ZIP либо по отдельности.
6. Откройте площадку штатной кнопкой, вставьте текст и загрузите файлы.
7. После публикации отметьте пакет как опубликованный; ссылку на пост можно сохранить.

Bamboo не копирует сессию браузера, не хранит cookies и не вызывает закрытые web-endpoints. Пароль остаётся только на сайте площадки.

## Ярмарка мастеров: заполнение через авторизацию в браузере

Для Ярмарки мастеров реализован отдельный browser-assisted flow. Это не OAuth и не серверная имитация пользователя.

1. В карточке изделия заполните раздел **Ярмарка мастеров** и выберите нужные фото.
2. Создайте публикацию для канала **Ярмарка мастеров**.
3. В истории нажмите **Открыть пакет**.
4. Один раз перетащите кнопку **Bamboo → заполнить Ярмарку** на панель закладок.
5. Нажмите **Скопировать данные для помощника**.
6. Откройте `livemaster.ru`, войдите обычным способом и откройте форму добавления работы.
7. Нажмите сохранённую закладку.
8. Помощник попытается заполнить пустые поля: название, краткое и полное описание, цену, материалы, размеры, ключевые слова и наличие.
9. Проверьте результат, загрузите фото из ZIP и нажмите штатную кнопку публикации самостоятельно.

Граница безопасности:

- помощник читает только JSON из буфера обмена и видимые поля текущей страницы;
- не читает `document.cookie`, пароль, local storage или сетевые запросы;
- не отправляет данные в Bamboo или другие сервисы;
- не перезаписывает уже заполненные поля;
- не нажимает кнопку окончательной публикации;
- браузер не позволяет скрытно подставлять локальные файлы, поэтому фото добавляются из ZIP вручную.

## Почему автоматические интеграции требуют специальные аккаунты

Требования задаются самими площадками, а не Bamboo. Полная автоматизация может требовать:

| Площадка | Что обычно требуется для API-режима |
|---|---|
| YouTube | Google Cloud project, OAuth client, YouTube channel и разрешения API |
| Pinterest | business account, developer app, OAuth и одобренный уровень доступа |
| TikTok | developer app, Content Posting API, тестовые пользователи и/или audit |
| Instagram | Professional account, связанная Facebook Page, Meta app и permissions |
| Facebook | Facebook Page, Meta app и permissions |
| VK | приложение, пользовательский access token и необходимые права |

Поэтому API находится под раскрываемым разделом **«Автоматически через официальный API — расширенный режим»** и не является обязательным первым шагом.

Telegram подключается проще остальных:

```text
BotFather → токен → @имя_канала → проверить
```

Подробности: [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

## Обновление

```bash
./scripts/update.sh
```

Updater создаёт резервную копию, загружает актуальный `main`, пересобирает контейнер, применяет миграции, перезапускает Hub и выполняет smoke test. Пользовательские изменения не сбрасываются автоматически.

После обновления проверьте:

```bash
curl -fsS http://localhost:8080/health/version
```

Если браузер показывает старую страницу, выполните жёсткое обновление `Ctrl+Shift+R` или `Cmd+Shift+R`. CSS и JavaScript версии 0.3.0 имеют cache-busting query string, поэтому обычное обновление также должно загрузить новые ресурсы.

## Принцип интеграций

Основной пользовательский путь не зависит от скрытых API, сохранённых браузерных cookies или n8n. Официальные API используются только там, где пользователь сознательно выбирает полную автоматизацию и выполняет требования площадки.
